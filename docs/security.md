# Security and privacy

Joke retrieval endpoints are public and read-only. The API also supports anonymous owner tokens for owner-scoped resources, linked tokens for automation, and an operator token for protected operations. The operator token is generated on first startup, stored in the private `secrets.yml` file, and printed once to the startup console. Treat it as a password: do not put it in source control, URLs, browser storage, or logs. Owner tokens are managed at `/server/preferences/tokens`; use a linked token for automation and revoke it when it is no longer needed. MCP requests require a Bearer token.

Each internal metrics service requires its own Bearer token from `server.metrics.auth.tokens.<service>` (the generated values are kept in `secrets.yml`); missing or invalid credentials receive 401. The server stores owner token hashes and encrypted reveal copies in its SQLite database. A separate persistent installation secret signs rotating security-report links and contact form tokens. Back up the database and private configuration together.

The public contact form supports security, abuse, DMCA, and privacy report types with validation, CAPTCHA, and a review step. Security reports are encrypted and stored; when an active PGP key exists, report bodies use that key, and otherwise use the installation AES key. Status links are single-use-token protected. When valid SMTP and recipient addresses are configured, the security contact receives the encrypted report, the researcher receives an acknowledgment, and status changes send an update. Security webhooks receive a summary without the report body. If SMTP is unavailable or no recipient is configured, those emails are not sent. Never include credentials or private data in public issues.

Operators manage the disclosure key with `jokes --maintenance pgp generate`, `rotate`, `publish`, `export public`, `export private`, `import`, and `delete`. The private key is encrypted with the persistent installation secret. Backups include the security key directory and database so a restore retains the key needed for encrypted reports. Key publication can be disabled with `web.security.publish_pgp_key`; see the [configuration reference](configuration.md).

The server adds browser security headers, including a restrictive Content Security Policy, frame protection, and MIME sniffing protection. Configure trusted proxies explicitly when TLS terminates upstream so public URLs and secure cookies use forwarded request metadata only from trusted peers. Deployments should keep the binary and private configuration current.

GeoIP country filtering is a deny-only risk signal. It runs after request rate limiting, bypasses private/internal and configured allowlisted addresses, and never replaces authentication or authorization. Missing, stale, or unreadable databases fail open for requests and appear in health checks. The data is downloaded from ip-location-db with checksum verification; City data is from DB-IP and is credited on `/server/about` and in `LICENSE.md`.

The service has public `/server/privacy`, `/server/terms`, `/server/healthz`, and `/server/security` pages. Health output must not be treated as a source of private deployment details. Guest browser preferences are stored in cookies; the sync flow excludes consent and credentials.

`server.privacy.data.sold` defaults to `false`, which displays that personal information is not sold or shared. Setting it to `true` enables the CCPA/CPRA opt-out controls on the privacy and preferences pages and changes the privacy notice. The browser choice is stored in the `ccpa_opt_out` cookie. Operators are responsible for making the notice match actual data practices.
