# Configuration

The server loads `server.yml` from its configuration directory. `--config` or `CONFIG_DIR` selects that directory. Settings may also appear in any YAML file in `yaml.d/`; maps merge recursively in filename order, and `secrets.yml` is merged last. Invalid values fall back to their defaults with warnings, while an unparseable file uses its last valid contents or built-in defaults. Configuration errors do not stop server startup. Command-line `--address`, `--port`, and `--baseurl` override those values. `--data`, `--cache`, `--log`, `--backup`, and `--pid` select their corresponding runtime paths; the matching `DATA_DIR`, `CACHE_DIR`, `LOG_DIR`, `BACKUP_DIR`, and `PID_FILE` environment variables are also supported by the path layer. Runtime startup creates the selected configuration, data, cache, log, backup, and PID-parent directories when needed.

The current configuration model is deployment-specific and is not shipped as a single example file. Configuration files do not belong in source control. The application writes generated credentials to a private `secrets.yml`; do not publish or manually copy those values into `server.yml`.

On Linux system installs, startup checks the configured backup directory by creating and removing a probe as the `jokes` service account. A failed check logs one error with the path, owner, mode, and service user, but does not stop the server. Backup attempts then fail with the same diagnostic; the server never redirects backups to a different directory.

## Server settings

| YAML key | Description |
|---|---|
| `server.lang` | Default server command output language. `auto` follows `LC_ALL`, `LC_MESSAGES`, then `LANG`; a supported language code selects that locale. The `--lang` flag takes precedence. |
| `server.address`, `server.port` | Listen address and port. The container image uses port 80; the binary's generated port may be selected dynamically. |
| `server.baseurl` | Optional normalized URL path prefix for reverse-proxy subpath deployments; defaults to `/`. Trusted forwarded prefix headers take precedence per request. |
| `server.fqdn`, `server.title`, `server.description`, `server.mode`, `server.pidfile` | Server identity, run mode, and PID-file behavior. |
| `server.rate_limit.read`, `.write`, `.health`, `.strict`, `.auth_failures`, `.global_burst` | Mandatory sliding-window request limits by endpoint class and client identity. Rate limiting is always on; each class has `requests` and `window` values, and `global_burst` is the per-client ceiling across classes. Defaults are 120/60s read, 10/60s write, 120/60s health, 10/900s strict, 5/900s failed authentication, and 240 global requests per minute. |
| `server.csrf.enabled`, `.secure`, `.exempt_paths[]` | Frontend-only CSRF protection defaults on. `secure` accepts `auto`, `true`, or `false` (`auto` follows HTTPS); exemptions are frontend URL path globs only. Cookie name, header name, and 32-byte token size are fixed. API and compatibility routes are outside CSRF validation. |
| `server.limits.max_body_size`, `.read_timeout`, `.write_timeout`, `.idle_timeout` | HTTP request limits from `yaml.d/security.yml`; defaults are `10MB`, `30s`, `30s`, and `120s`. Invalid or non-positive values fall back individually to defaults with a warning that names the file, line, and key. A valid limits change updates the body cap immediately and transfers listeners to a replacement HTTP server generation, then drains existing requests without closing the bound sockets. |
| `server.healthz.root.enabled` | Mount `/healthz` directly to the canonical `/server/healthz` handler; defaults to `false`. The versionless `/api/healthz` alias is independent. |
| `server.contact.admin.email` | Private operator notification mailbox. It is never published by a public page or endpoint. |
| `server.logs.level`, `.defaults`, `.access`, `.server`, `.error`, `.audit`, `.security`, `.debug` | Per-kind log format, file path, level, rotation, retention, and compression settings. Enabled logs are written as ASCII text; audit entries use JSON Lines and a verified SHA-256 chain with a persistent anchor. The scheduler closes/reopens configured files around rotation. |
| `server.ssl.enabled`, `.cert`, `.key`, `.letsencrypt.*` | TLS enablement, optional manually supplied certificate/key paths, and Let's Encrypt settings. ## Configuration files and secrets

`server.yml` is the primary settings file. Any setting may appear in any `yaml.d/` drop-in; files merge in byte-wise filename order and later values override earlier values. `server.baseurl` must be an origin-relative path prefix, such as `/myproject`; trailing slashes are removed, an empty value means `/`, and trusted proxy prefix headers override it for each request. `secrets.yml` stores generated and operator-supplied credentials with restrictive file permissions; do not place secret values in source control. The SQLite database stores the persistent installation secret and token state. Back up the configuration directory and application data together; never add either to a public repository.

On startup, the obsolete `server.rate_limit.enabled`, `.requests`, and `.window` keys are removed because rate limiting is always enabled and limits are configured by endpoint class. Before removing these keys, the server saves the original file as `server.yml.bak` (or the source drop-in's `.bak` copy).

Custom email templates use `{config_dir}/template/email/{name}.txt`. Each file starts with `Subject: ...`, a `---` separator, and a plain-text body using `{variable}` placeholders. Overrides are read for each send; invalid overrides are ignored with a warning and the embedded default is used. Templates are wired for startup/shutdown, backup failure, low-disk alerts, contact submissions, encrypted security-report notices, researcher acknowledgments, and status changes. Other built-in operator event templates still need their event sources connected.

GeoIP databases are downloaded at first run and updated weekly by the built-in scheduler. Downloads are checksum-verified and stored under the data directory's `security/geoip` directory. Missing or stale databases do not block requests; country filtering fails open and health reports the database status. Country filtering runs after rate limiting. Private/internal and allowlisted addresses bypass country lookup.

Blocklists are stored under `security/blocklists/`. The built-in `firehol_level1` source cannot be disabled; operator sources use unique lowercase IDs, a declared `ip` or `domain` type, and HTTPS URLs. Each source is updated atomically by the built-in daily scheduler, and a failed update leaves its last good copy active. The middleware checks client IPs and submitted Origin/Referer, email-domain, and URL targets. Freshness is fixed at 72 hours and appears as per-source checks on the health endpoint. Low disk notifications run on the configured built-in scheduler interval and recover after usage drops five percentage points below the threshold.

`--maintenance backup [filename]` creates and verifies a root-layout `.tar.gz` archive. Manifests record `type`, UTC `snapshot_at`, per-file metadata for full snapshots, and a canonical `sha256` over sorted file digest/path lines; incrementals bind `base_sha256` to the base manifest's `sha256`. It includes configuration files and an existing local SQLite database; `--include-data` and `--include-ssl` add their respective directories. A configured `server.backup.encryption_password` encrypts the archive and adds the `.enc` suffix. Without it, the command warns that the archive is unencrypted. The built-in `backup_daily` task creates a verified dated full archive and daily incremental, and `backup_hourly` creates hourly incrementals when enabled. Retention preserves any full backup needed by retained incrementals. `--maintenance backup test [file]` verifies a selected archive without changing live data. Remote libSQL is supported for normal database access and can be seeded from a restored local SQLite snapshot when the remote database is empty. `--maintenance restore <file>` verifies and stages an archive before installing it. First-run restore is allowed only for an empty local SQLite database or an empty remote libSQL database. Root restore requires interactive confirmation; the `jokes` service account must enter the operator token.

The service has no web-based configuration editor. A configuration watcher detects file and asset changes and reapplies supported settings, including `server.baseurl`, request limits, and HTTP timeouts. Restart the server after changing the listener address/port, database driver, TLS lifecycle, or service settings; consult the release notes for the settings supported by the running version's reload path.
